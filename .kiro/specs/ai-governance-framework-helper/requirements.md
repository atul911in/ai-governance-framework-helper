# Requirements Document

## Introduction

The AI Governance Framework Helper is an application that assists users in navigating AI governance requirements across different countries and regulatory frameworks. Users input their project details, select the relevant country governance framework, and receive tailored advice with appropriate depth and specificity. The system bridges the gap between complex regulatory documents and actionable project-level guidance.

## Glossary

- **Governance_Framework**: A structured set of principles, guidelines, and regulations governing the development and deployment of AI systems within a specific jurisdiction (e.g., EU AI Act, Singapore PDPA + Model AI Governance Framework, NIST AI RMF, ISO 42001).
- **Project_Profile**: A structured collection of user-provided information about their AI project including purpose, data types, risk level, deployment context, and affected stakeholders.
- **Risk_Classification**: The categorization of an AI system's risk level (e.g., unacceptable, high, limited, minimal) as defined by the selected governance framework.
- **Compliance_Advice**: Tailored recommendations generated by the system based on the intersection of the user's project profile and the selected governance framework requirements.
- **Framework_Selector**: The interface component that allows users to choose one or more country-specific governance frameworks for analysis.
- **Input_Form**: The interface component where users provide their project requirements and details.
- **Advice_Engine**: The backend component responsible for analyzing project profiles against governance frameworks and generating compliance advice.
- **Detail_Level**: The granularity of advice provided, ranging from executive summary to detailed implementation guidance.

## Requirements

### Requirement 1: Project Information Input

**User Story:** As a project manager, I want to input my AI project details in a structured form, so that the system can understand my project context and provide relevant governance advice.

#### Acceptance Criteria

1. THE Input_Form SHALL provide fields for project name, project description, AI techniques used, data types processed, intended deployment region, target users, and intended purpose.
2. WHEN a user submits the Input_Form with all required fields completed, THE System SHALL validate the input and create a Project_Profile.
3. IF a user submits the Input_Form with missing required fields, THEN THE System SHALL highlight the missing fields and display a descriptive error message for each.
4. THE Input_Form SHALL allow users to specify the industry sector of their AI project from a predefined list of sectors including Banking, Insurance, Health, Retail, Technology, Government, Education, Manufacturing, and Telecommunications.
5. WHEN a user provides free-text project description, THE System SHALL accept descriptions between 50 and 5000 characters in length.

### Requirement 2: Governance Framework Selection

**User Story:** As a compliance officer, I want to select one or more country-specific AI governance frameworks, so that I can receive advice tailored to the jurisdictions relevant to my project.

#### Acceptance Criteria

1. THE Framework_Selector SHALL display a list of available governance frameworks organized by country or region.
2. THE Framework_Selector SHALL support selection of at least the following frameworks: EU AI Act, Singapore Model AI Governance Framework, US NIST AI Risk Management Framework, UK AI Regulation Policy, Canada Artificial Intelligence and Data Act, Australia AI Ethics Framework, and ISO 42001 (AI Management System Standard).
3. WHEN a user selects multiple frameworks, THE System SHALL generate comparative advice highlighting differences and overlaps between the selected frameworks.
4. THE Framework_Selector SHALL display a brief summary description for each available governance framework before selection.
5. IF a user proceeds without selecting any governance framework, THEN THE System SHALL prompt the user to select at least one framework before generating advice.

### Requirement 3: Risk Classification

**User Story:** As a developer, I want the system to classify my AI project's risk level according to the selected governance framework, so that I understand the regulatory tier my project falls into.

#### Acceptance Criteria

1. WHEN a Project_Profile is submitted with a selected Governance_Framework, THE Advice_Engine SHALL determine the Risk_Classification for the project according to each selected framework's criteria.
2. THE Advice_Engine SHALL display the Risk_Classification result with a clear explanation of why the project was classified at that level.
3. WHEN the Risk_Classification is high or unacceptable under any selected framework, THE System SHALL prominently flag this classification with specific regulatory obligations.
4. IF the provided project information is insufficient to determine a definitive Risk_Classification, THEN THE System SHALL indicate the ambiguity and request additional clarifying information from the user.

### Requirement 4: Compliance Advice Generation

**User Story:** As a project lead, I want to receive actionable compliance advice based on my project profile and selected frameworks, so that I can take concrete steps toward regulatory compliance.

#### Acceptance Criteria

1. WHEN a Project_Profile and at least one Governance_Framework are provided, THE Advice_Engine SHALL generate Compliance_Advice within 30 seconds.
2. THE Compliance_Advice SHALL include specific obligations, recommended actions, documentation requirements, and relevant timelines derived from the selected Governance_Framework.
3. THE Compliance_Advice SHALL be organized into categories: data governance, transparency, accountability, fairness, safety, and human oversight.
4. WHEN multiple frameworks are selected, THE Advice_Engine SHALL identify conflicting requirements between frameworks and suggest a harmonized approach.
5. THE Advice_Engine SHALL provide references to specific sections or articles of the source governance framework documents for each piece of advice.

### Requirement 5: Detail Level Control

**User Story:** As a user, I want to control the level of detail in the advice I receive, so that I can get an executive summary or deep-dive guidance depending on my needs.

#### Acceptance Criteria

1. THE System SHALL offer three Detail_Level options: Executive Summary, Standard, and Detailed Implementation Guidance.
2. WHEN the user selects Executive Summary, THE Advice_Engine SHALL provide a concise overview of key obligations and risk classification in no more than 500 words.
3. WHEN the user selects Detailed Implementation Guidance, THE Advice_Engine SHALL provide step-by-step implementation recommendations, checklist items, and template suggestions.
4. THE System SHALL default to the Standard Detail_Level when no explicit selection is made by the user.

### Requirement 6: Advice Export and Sharing

**User Story:** As a compliance officer, I want to export the generated advice as a document, so that I can share it with stakeholders and include it in project documentation.

#### Acceptance Criteria

1. WHEN a user requests an export, THE System SHALL generate a downloadable document in PDF format containing the full Compliance_Advice.
2. THE exported document SHALL include the Project_Profile summary, selected frameworks, Risk_Classification, and all generated Compliance_Advice.
3. THE System SHALL include a timestamp and version identifier in each exported document.
4. THE System SHALL support export in both PDF and Markdown formats.

### Requirement 7: Framework Knowledge Currency

**User Story:** As a user, I want to know that the governance framework information is current, so that I can trust the advice reflects the latest regulatory requirements.

#### Acceptance Criteria

1. THE System SHALL display the last-updated date for each Governance_Framework's knowledge base.
2. WHEN a Governance_Framework has been updated within the last 30 days, THE System SHALL display a notification indicating recent changes.
3. THE System SHALL display a disclaimer stating that the advice is informational and does not constitute legal counsel.

### Requirement 8: AI Technology and Platform Recommendations

**User Story:** As a developer, I want to receive recommendations on AI technology choices, cloud platforms, and LLM models suited to my project, so that I can make informed decisions on implementation tools that align with governance requirements.

#### Acceptance Criteria

1. WHEN a Project_Profile and Governance_Framework selection are complete, THE Advice_Engine SHALL generate technology recommendations including cloud platform options from AWS, Azure, and Google Cloud AI services.
2. THE Advice_Engine SHALL recommend AI orchestration frameworks relevant to the project type, including options such as LangGraph, LangChain, Semantic Kernel, and Amazon Bedrock Agents.
3. THE Advice_Engine SHALL recommend suitable LLM models with the following details for each: model name, provider, key capabilities, context window size, and approximate cost per token.
4. THE Advice_Engine SHALL present pros and cons for each recommended technology choice in relation to the user's project requirements and selected governance framework.
5. WHEN a Governance_Framework imposes data residency or processing constraints, THE Advice_Engine SHALL filter technology recommendations to include only platforms and models that support compliant deployment regions.
6. THE Advice_Engine SHALL organize technology recommendations into categories: Cloud Platform, AI Orchestration Framework, and LLM Model Selection.
